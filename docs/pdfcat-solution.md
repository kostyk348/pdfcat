# pdfcat — решение: организатор каталогов PDF с сетевого диска (Win7, Rust, ноль зависимостей)

Версия 1.0 · 2026-11-20 · Specessa · код: `workspace/pdfcat` (собран, 17/17 тестов, exe Win7 514 КБ)

---

## 1. Требования ТЗ и проверяемость

| # | Требование | Проверяемо | Чем |
|---|---|---|---|
| 1 | Указал сетевой диск → каталог со всеми папками/подпапками/PDF как граф | **да** | `pdfcat scan <UNC>`, инвариант `Catalog::verify()`, тест на дереве с кириллицей |
| 2 | Поиск по имени | **да** | `pdfcat search`, тест |
| 3 | Полнотекстовый поиск PDF (BM25) | **да** | BM25-индекс, тесты релевантности + персистентности; E2E на кириллице |
| 4 | **Только чтение сетевого диска** (требование владельца, 2026-11-20) | **да** | сканер не пишет ни байта: только `read_dir` + `read`; база каталога/индекса — локальные файлы рядом с exe (опция `--db`); в коде нет ни одного пути записи по корню скана |
| 5 | Windows 7 без проблем | **да** | rustc 1.77.2, target `x86_64-pc-windows-gnu`, exe 514 048 Б; импорты — ядро NT + UCRT (KB2999226), как у dxfsign |
| 6 | Строго типизированная память | **да** | SoA-пулы (`EntryPool`, `DirPool`), арена строк, u32-индексы вместо ссылок, поколения не нужны (append-only) |
| 7 | Отсутствие GC в главном цикле | **да** | все структуры — владение Rust; в скан-цикле 2 арена-вставки на файл, 0 аллокаций на каталог-переход |
| 8 | SIMD | **да** | BM25-развёртка: AVX2-батчи по 8 постингов с `vpgatherdd` по длинам документов; `sum_f32` AVX2/SSE2; рантайм-детект, скалярный fallback (Win7/старые CPU) |
| 9 | UI Bento Grids | частично | спецификация числами (§5); окно — этап E1 (в скелете CLI) |
| 10 | «Удобный поиск» | не задано → решено | имена + текст одновременно; сниппеты — E5; фильтры — E5 |

## 2. Конфликты и чем платим

| Конфликт | Суть | Решение | Чем платим |
|---|---|---|---|
| «Ноль зависимостей» vs PDF-формат | PDF — 750+ страниц стандарта; полная поддержка = зоопарк фильтров и шрифтов | собственное подмножество с честным отказом (см. §4) | PDF 1.5+ (xref/object streams), `/Differences`, LZW, RunLength, шифрованные файлы и сканы без текстового слоя пропускаются с причиной |
| «Ноль зависимостей» vs рендер | нормальный UI обычно = wgpu/egui | GDI DoubleBuffering, как в dxfsign | нет аппаратного ускорения — но у нас текст и плитки, не игры; бюджет кадра < 8 мс достижим |
| BM25 «в файл» vs скорость загрузки | полный индекс в память | персистентный бинарник `PDFBM25 1`, чтение одним проходом | память O(токены); для 100k PDF ≈ сотни МБ — ротация/сжатие в E4 |
| Win7 vs современный Rust | новейшие крейты требуют 1.80+ | пин 1.77.2 + zero-dep | часть удобств std после 1.77 недоступна — обходится |
| «Каталог как граф» vs дерево ФС | ФС — дерево, граф требует связей файлов | дерево каталогов + связи «файл ↔ папка»; граф-вид — этап E5 | настоящий граф (ссылки между PDF) — позже, не фейк в MVP |

## 3. Стек: Rust и что он НЕ даёт

| Нужно | Что есть | Чего нет и как закрываем |
|---|---|---|
| Скан UNC | `std::fs::read_dir` работает с UNC | нет событий изменения → E3: `ReadDirectoryChangesW` |
| Декомпресс PDF | свой inflate (stored/fixed/dynamic + zlib + Adler-32) | нет zlib-крейта — свой, проверен фиксчурами, сгенерированными независимо (Python zlib) |
| PDF-текст | свой парсер (§4) | нет ToUnicode-стандарта — подмножество bfchar/bfrange; остальное — честный `Unsupported` |
| Поиск | свой BM25 Okapi (k1=1.2, b=0.75) | нет лемматизации — стемминг Cyrillic Snowball как опция E4 |
| SIMD | `core::arch` AVX2 + рантайм-детект | scatter в AVX2 нет — 8 скалярных инкрементов после векторной арифметики |
| Окно Win7 | GDI + `RegisterClassExW`, как в dxfsign | нет DPI-осведомлённости нового API — `SetProcessDPIAware` |

## 4. Покрытое подмножество PDF (честно)

| Поддержано | Не поддержано (пропуск с причиной) |
|---|---|
| классический xref + надёжный fallback-скан «N G obj» | xref/object streams (PDF 1.5+) |
| `/FlateDecode` (свой inflate) и потоки без фильтра | LZW, RunLength, DCT-потоки (текст в них не текст) |
| literal `(...)` и hex `<...>` строки, все экранирования | шифрованные PDF (RC4/AES) |
| простые шрифты WinAnsi/PDFDocEncoding | `/Differences`-кодировки |
| Type0/Identity-H через `/ToUnicode` (bfchar + bfrange) — **кириллица из Word-экспортов** | шрифты без ToUnicode с экзотическими кодировками |
| операторы BT/ET Tf Tj TJ ' " Td TD Tm T*, `/Length` (в т.ч. косвенная) | OCR (сканы без текстового слоя) — вне MVP по YAGNI |
| страницы через `/Root`→`/Pages`→`/Kids`, лимиты MAX_PAGES=10 000, MAX_STREAM=256 МБ | |

Каждый пропуск — `ExtractError::Unsupported("причина")`, виден в `pdfcat index` и в UI плитки «Ошибки».

## 5. UI Bento Grids — реализация числами (GDI, Win7)

| Параметр | Значение |

| Типоразмеры плиток | S 1×1 = **232×160** · M 2×1 = **472×160** · L 2×2 = **472×328** · XL 3×2 = **712×328** |
| Зазор / радиус | 8 px / 10 px (`RoundRect`), кант 1 px |
| Палитра | фон `#0F1115` · плитка `#171A21` · hover `#1E2530` · кант `#2A3140` · текст `#E6EAF2` · muted `#9AA6B8` · акцент `#6EE7F9` · ok `#34D399` · bad `#FB7185` |
| Типографика | Segoe UI 13/15/18/24; цифры табличные (`tabular-nums` — GDI: моноширинная подмена в числовых полях) |
| Плитки v1 | «Поиск» (M, поле ввода) · «Каталог» (L, дерево) · «Результаты» (XL, список хитов + сниппеты) · «Последние» (M) · «Статистика» (S: файлы/объём/ошибки) · «Превью» (L, текст страницы) |

| Рендер | memory DC + `BitBlt`, кеш глифов ≤ 8 МБ (перенос из dxfsign), бюджет кадра < 8 мс, FPS не нужен (перерисовка по событиям) |

## 7. Сложность горячих операций (O и 10×)

| Операция | Сложность | На 10× данных |
|---|---|---|
| Скан | O(файлы+каталоги), память O(имена) | линейно; UNC-латентность съест больше, чем CPU → параллельный обход (E4) |
| Парсинг PDF (fallback-индекс объектов) | O(размер файла) | линейно; xref-путь быстрее, но fallback — страховка |
| Извлечение текста | O(контент + inflвые байты) | линейно; параллелизм по файлам (E4) |
| Построение BM25 | O(токенов) | линейно (замерено) |
| Поиск | O(сумма постингов термов запроса) | рост по N файлов линейный; top-k сейчас сортировкой O(N log N) → k-heap в E1 |
| Загрузка индекса | O(размер файла индекса) | линейно; 100k PDF ≈ сотни МБ — mmap-режим/сжатие в E4 |

## 8. Архитектура (границы)

```
┌─────────────────────────────────────────────────────────┐
│ Приложение: CLI (готово) · окно Bento (E1)               │
├─────────────────────────────────────────────────────────┤
│ Порты: Source · TextExtractor · Searcher · CatalogStore  │
├─────────────────────────────────────────────────────────┤
│ Домен (DDD): Catalog + инварианты + TextIndexed-событие  │
│ Память (DOP): StringArena · EntryPool · DirPool (SoA)    │
├─────────────────────────────────────────────────────────┤
│ Адаптеры: FsScanner (только чтение!) · PdfExtractor      │
│           Bm25 (+PDFBM25 1) · CatalogStore (PDFCAT 1)    │
│ Ядра: inflate (свой) · SIMD (AVX2/SSE2/скаляр)           │
└─────────────────────────────────────────────────────────┘
```

- Домен не знает про ФС, PDF и поиск; адаптеры не знают друг о друге; сборка — только в `cli.rs`/`ui.rs`.
- **Read-only инвариант**: ни один адаптер не пишет по корню скана; все записи — локальные файлы БД
  (позже `%LOCALAPPDATA%\pdfcat\`), проверяемо тестом «после scan/index/search дерево скана байт-в-байт не изменилось» (E1).

## 9. План этапов

| Этап | Что | Проверяемо |
|---|---|---|
| **E0 — готово** | скелет: скан/парсинг/BM25/персистентность/CLI, Win7-сборка | 17 тестов + замеры §6 |
| **E1** | окно Bento (§5) на GDI; тест «сетевой диск не изменён» (хэш дерева до/после) | скриншоты + хэш |
| **E2** | PDF 1.5: xref streams, object streams; `/Differences`; LZW | доки с Acrobat 2024, byte-точные фикстуры |
| **E3** | наблюдение за изменениями (`ReadDirectoryChangesW`), инкрементальный индекс | файл добавлен → в поиске за < 2 с без полного реиндекса |
| **E4** | параллельная индексация (потоки, воркеры), SIMD-токенизатор, mmap-индекс, k-heap | 10× замер: 1200 PDF ≤ 2,5 с |
| **E5** | сниппеты попаданий, сохранённые фильтры (граф-вид перенесён в E1 — решение владельца) | UI-скриншоты |
| **E6** | сжатие индекса + лимиты памяти (100k PDF), полировка лимитов MAX_PAGES/MAX_STREAM по реальным файлам | замер памяти и загрузки на 100k |

## 10. Решения владельца (2026-11-20, зафиксировано)

| Вопрос | Решение |
|---|---|
| Где хранить локальную БД | **Рядом с exe** (портативно). При отказе прав на папку exe — fallback `%LOCALAPPDATA%\pdfcat\` (прецедент: outbox dxfsign) |
| Граф или дерево | **Оба режима** с первого релиза UI: дерево (плитка «Каталог») и граф-вид (узлы-каталоги и PDF-файлы, клик → плитка файла) |
| OCR | **Никогда.** Сканы без текстового слоя ищутся только по имени; OCR в планах не существует |
| Неподдержанные PDF | Показывать отдельной плиткой «Ошибки/Не поддержано» с точной причиной из `ExtractError` |
